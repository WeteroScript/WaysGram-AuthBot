# WaysGram AuthBot

Единый сервер WaysGram и Telegram-бот авторизации. Процесс запускает Telegram-бота и HTTP API на одном приложении FastAPI; аккаунты, виртуальные номера, сессии, сообщения, балансы и подарки используют одну SQLite-базу.

## Виртуальные номера и вход

Бот выдаёт уникальный внутренний идентификатор формата `+1` и десять цифр. Это **виртуальный идентификатор WaysGram**, а не номер мобильного оператора: он не принимает звонки или SMS и используется только для входа в WaysGram.

Бот самостоятельно создаёт шестизначный одноразовый код. При входе через приложение пользователь запрашивает код, получает уведомление от AuthWaysGram_bot и открывает кнопку «Получить код». Код хранится в базе в зашифрованном виде, имеет ограниченный срок действия и лимит попыток. После успешной проверки API выдаёт сессию приложения. В базе сохраняется только SHA-256 хеш токена сессии; срок сессии — 30 дней.

Бот не читает SMS и не запрашивает коды личных аккаунтов официального Telegram. Для отдельного self-hosted MTProto-сервера WaysGram поддерживается доставка его собственного кода входа через подписанный webhook; это не код авторизации в официальной сети Telegram.

### Доставка кодов входа self-hosted MTProto-сервера

AuthBot может быть каналом доставки OTP для отдельного self-hosted MTProto-сервера, поддерживающего протокол webhook v1 (например, telesrv/OwpenGram). Сервер сам генерирует и проверяет код; AuthBot только доставляет этот же код пользователю через `@AuthWaysGram_bot`.

Для включения:

1. На Bothost добавь переменную `TELESRV_OTP_WEBHOOK_SECRET` в окружение AuthBot. Это отдельный длинный случайный секрет; сохрани его конфиденциально.
2. На MTProto-сервере задай те же значения:
   ```env
   TELESRV_PHONE_CODE_DELIVERY_PROVIDER=webhook
   TELESRV_PHONE_CODE_LENGTH=6
   TELESRV_OTP_WEBHOOK_URL=https://<домен-authbot>/v1/otp/deliveries
   TELESRV_OTP_WEBHOOK_SECRET=<тот-же-секрет>
   ```
3. Пользователь должен пройти CAPTCHA в AuthWaysGram_bot и получить виртуальный номер `+1XXXXXXXXXX`. Сервер должен отправлять `login_sms` с каналом `sms` и шестизначным кодом.

Маршрут `POST /v1/otp/deliveries` проверяет HMAC-SHA256 подпись, временную метку, назначение и подтверждение виртуального номера. Для номера принимаются оба представления одного виртуального US-идентификатора: `+1XXXXXXXXXX` и нормализованный `1XXXXXXXXXX`, который отправляет telesrv. Перед поиском владельца номер приводится к `+1XXXXXXXXXX`; номера других стран отклоняются. Повтор того же `delivery_id` не отправляет OTP повторно; повторное использование ID с другим телом отклоняется. Код сохраняется в AuthBot в зашифрованном виде и отправляется в личный чат бота.

Этот маршрут принимает только коды собственного self-hosted WaysGram MTProto-сервера. Он не получает, не запрашивает и не пересылает коды входа в официальную сеть Telegram. Он также не заменяет MTProto-сервер: сам AuthBot остаётся HTTP API и Telegram-ботом.

## Запуск

### Docker Compose

В репозитории есть `Dockerfile`, `docker-compose.yml` и безопасный шаблон `.env.example`. Для размещения на сервере:

1. Клонировать репозиторий на Docker-хост.
2. Скопировать шаблон: `cp .env.example .env`.
3. Заполнить в `.env` значения `BOT_TOKEN`, `INTERNAL_API_TOKEN` и `OTP_FERNET_KEY`.
4. Для полного каталога подарков дополнительно задать `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`. Без них AuthBot переключится на ограниченный резервный Bot API-каталог.
5. Запустить: `docker compose up -d --build`.
6. Проверить состояние: `docker compose ps`; endpoint проверки доступен на `http://127.0.0.1:8081/health`.

Compose создаёт постоянный named volume `waysgram_data` для SQLite. Не удаляй его при обновлении контейнера. Для удалённого Android-клиента API должен быть опубликован через HTTPS reverse proxy или HTTPS ingress; не открывай порт API напрямую в публичный интернет без TLS. В GitHub Actions Android-репозитория адрес внешнего HTTPS endpoint задаётся секретом `WAYSGRAM_API_BASE_URL`.

### Запуск в Termux (локальное тестирование)

Этот сценарий предназначен для короткого локального тестирования, когда Android-приложение и AuthBot запущены на одном устройстве. Для подключения с других устройств используй VPS и HTTPS reverse proxy.

1. Установи Termux из доверенного источника и открой его.
2. Клонируй репозиторий:
   `git clone https://github.com/WeteroScript/WaysGram-AuthBot.git`
3. Перейди в каталог и запусти установщик:
   `cd WaysGram-AuthBot && bash scripts/run-termux.sh`
4. При первом запуске скрипт создаст `.env` из шаблона и остановится, чтобы ты заполнил секреты.
5. Открой `.env`, задай `BOT_TOKEN`, `INTERNAL_API_TOKEN`, `OTP_FERNET_KEY` и свой Telegram ID в `ADMIN_ID`.
6. Для полного MTProto-каталога добавь `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`; без них будет доступен резервный Bot API-каталог.
7. Повтори `bash scripts/run-termux.sh`.

Для локального Android-клиента API-адрес должен быть `http://127.0.0.1:8081`. Не используй этот HTTP-адрес для удалённых клиентов через интернет; для них нужен HTTPS.

### Ручной запуск

Требуется Python 3.11+.

1. Установить зависимости: `pip install -r requirements.txt`.
2. Задать `BOT_TOKEN`, `INTERNAL_API_TOKEN` и `OTP_FERNET_KEY` в переменных окружения.
3. Запустить сервис командой из Procfile: `web: python bot.py`.

`BOT_TOKEN` не хранится в исходниках. Создать `OTP_FERNET_KEY` можно командой:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Создать случайный внутренний токен можно командой:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Сгенерированный `OTP_FERNET_KEY` нужно сохранить в секретах хостинга и не менять между перезапусками: он нужен для расшифровки ранее сохранённых кодов. Сервис использует long polling Telegram и одновременно поднимает HTTP API. API слушает `INTERNAL_API_PORT`, затем `PORT`, по умолчанию — 8081. Для продакшена необходим постоянный диск для `DATABASE_PATH`; временное файловое хранилище может потерять базу при перезапуске.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Обязательный токен Telegram-бота |
| `TELEGRAM_API_ID` | Необязательный API ID для bot-authenticated MTProto; нужен для полного каталога |
| `TELEGRAM_API_HASH` | Секретный API hash; используется вместе с `TELEGRAM_API_ID` |
| `ADMIN_ID` | Telegram ID администратора; по умолчанию 8888957702 |
| `DATABASE_PATH` | Путь к SQLite; по умолчанию `data/waysgram_authbot.sqlite3` |
| `MESSENGER_DATABASE_PATH` | Путь ко второму файлу SQLite (сообщения, группы, каналы, подарки); по умолчанию `<имя основного файла>_messenger.sqlite3` рядом с ним |
| `INTERNAL_API_TOKEN` | Секрет для внутренних серверных маршрутов |
| `OTP_FERNET_KEY` | Постоянный ключ шифрования одноразовых кодов |
| `INTERNAL_API_HOST` | Адрес привязки API; по умолчанию `0.0.0.0` |
| `INTERNAL_API_PORT` | Порт API; по умолчанию используется `PORT`, затем 8081 |
| `PUBLIC_API_BASE_URL` | Публичный origin API для ссылок-приглашений; задай внешний HTTPS-домен, если приложение работает за reverse proxy |
| `LOG_LEVEL` | Уровень логирования; по умолчанию `INFO` |

## Начальные балансы

При первом создании аккаунта WaysGram сервер одной SQL-транзакцией начисляет 5 000 внутренних Stars и 15 внутренних Gram. Повторное обновление профиля или повторная синхронизация номера не выдают бонус повторно. Обе операции записываются в `economy_transactions` как `welcome_bonus`.

## API приложения WaysGram

Клиентские маршруты используют Bearer-сессию. Для получения сессии пользователь должен иметь виртуальный номер и пройти CAPTCHA в AuthWaysGram_bot. Все идентификаторы пользователей в API — это реальные Telegram ID соответствующих аккаунтов WaysGram; отдельная таблица пользователей для второго backend не создаётся.

### Авторизация и профиль

- `POST /api/auth/request-code` — JSON `{"phone":"+1XXXXXXXXXX"}`; запросить код. Уведомление приходит через AuthWaysGram_bot, код пользователь забирает в боте. Для каждого виртуального номера действует лимит запросов; дополнительные запросы ограничиваются также на уровне IP.
- `POST /api/auth/verify-code` — JSON `{"phone":"+1XXXXXXXXXX","code":"123456"}`; проверить код и получить `token`.
- `POST /api/auth/refresh` — продлить действующую сессию.
- `POST /api/auth/logout` — завершить текущую сессию.
- `GET /api/me` и `PATCH /api/me` — получить или обновить username и отображаемое имя.
- `GET /api/users?q=...` и `GET /api/users/{telegram_id}` — поиск и просмотр публичного профиля.

### Переписка и каналы

- `GET /api/conversations` — список диалогов с последним сообщением.
- `GET /api/messages?with={telegram_id}` — последние сообщения; `after_id` — новые после указанного ID; `before_id` — предыдущая страница истории. Одновременно указывается только один курсор.
  Для активного диалога можно добавить `after_id` и `wait_seconds=20`: API подождёт новые сообщения до 20 секунд и вернёт их сразу после появления. Для обычной загрузки истории `wait_seconds` не требуется.
- `POST /api/messages` — JSON `{"recipient_id":123,"body":"Текст"}`; отправить личное сообщение. Поддерживает `Idempotency-Key` для безопасного повтора после сетевого сбоя.
- `GET /api/channels`, `GET /api/channels/{id}` — список и карточка канала.
- `POST /api/channels` — создать канал; JSON содержит `title`, `username` для публичного канала и `is_public` (boolean). Для приватного канала передай `is_public: false`; сервер вернёт `invite_link`.
- `GET /api/channels/invites/{token}` — проверить приглашение без вступления.
- `POST /api/channels/join` — вступить по `invite_link` или `invite_token`.

Для корректных внешних ссылок за reverse proxy задай `PUBLIC_API_BASE_URL=https://<публичный-домен>`. Для текущего размещения WaysGram на Bothost Dockerfile и Compose используют `PUBLIC_API_BASE_URL=https://bot-1793554244-6434-weterochina.bothost.tech` по умолчанию; значение из окружения имеет приоритет. При запуске через Procfile или собственную команду запуска добавь эту переменную в окружение сервиса. Без неё сервер использует origin текущего HTTP-запроса.
- `GET /api/channels/{id}/messages?after_id=...` — получить публикации.
  Для ленты в открытом экране поддерживается `wait_seconds=20` вместе с `after_id`; максимальное ожидание — 20 секунд.
- `POST /api/channels/{id}/messages` — опубликовать сообщение; доступ владельцу или администратору канала. Поддерживает `Idempotency-Key`.
- `POST /api/channels/{id}/admins` и `DELETE /api/channels/{id}/admins/{telegram_id}` — управление администраторами канала его владельцем.
- `DELETE /api/channels/{id}` — удалить собственный канал.

Лимит текста сообщения — 4000 символов. Ограничение отправки: 30 личных сообщений в минуту и 20 публикаций канала в минуту. Истории поддерживают инкрементальное чтение через `after_id`.

### Группы

- `GET /api/groups` — группы текущего пользователя.
- `POST /api/groups` — создать группу; JSON содержит `title`, необязательные `username` и `description`.
- `GET /api/groups/{id}` — сведения о группе и участниках; доступ только участникам.
- `POST /api/groups/{id}/members` — добавить участника по `telegram_id` или `username`; требуется роль владельца или администратора.
- `DELETE /api/groups/{id}/members/{telegram_id}` — покинуть группу или удалить участника с проверкой роли.
- `POST /api/groups/{id}/admins` / `DELETE /api/groups/{id}/admins/{telegram_id}` — назначение и снятие администраторов владельцем.
- `GET /api/groups/{id}/messages?after_id=...` и `POST /api/groups/{id}/messages` — история и отправка текста.
  Для открытого экрана группы чтение с `after_id` поддерживает `wait_seconds=20`.

Создатель получает роль владельца. Проверка членства выполняется для каждой операции чтения и отправки.

### Изображения, документы и медиа в сообщениях

- `POST /api/media/images` — загрузить статичное изображение JPEG, PNG или WebP.
- `POST /api/media/documents` — загрузить PDF, TXT, CSV, ZIP, видео MP4/M4V/MOV/WebM/MKV или аудио MP3/M4A/OGG/WAV. Передай исходные байты в теле запроса, соответствующий `Content-Type` и имя файла в percent-encoded заголовке `X-Filename`.
- `GET /api/media/{media_id}` — получить вложение после проверки сессии и доступа к соответствующему сообщению/чату.
- `GET /api/media/shared?scope=dm|group|channel&peer_id=...` — получить общие вложения чата с необязательными фильтрами `kind=image|video|audio|document`, `before_id` и `limit`.
- `POST /api/messages`, `POST /api/groups/{id}/messages`, `POST /api/channels/{id}/messages` — прикрепить загруженный файл через поле `media_id`. При пустом тексте сервер подставляет подпись по типу и имени вложения.

Изображения ограничены 10 MiB, максимальная сторона — 8192 пикселя, общий лимит — 40 мегапикселей. Сервер декодирует и пересохраняет изображения, удаляя исходные метаданные. Остальные вложения ограничены 25 MiB. PDF проверяется по сигнатуре и завершающему маркеру; TXT/CSV принимаются только как UTF-8 без NUL и недопустимых управляющих символов. Видео, аудио и ZIP проверяются по допустимому расширению, MIME-типу и файловой сигнатуре; архивы не распаковываются сервером. HTML, SVG, исполняемые файлы и неподдерживаемые типы отклоняются. Изображения, видео и аудио отдаются inline; документы и ZIP — как attachment. Для всех ответов применяется `X-Content-Type-Options: nosniff`.

На аккаунт действует общая квота 100 MiB и ограничение 30 загрузок в час для медиа. Вложения доступны владельцу и участникам соответствующего диалога/группы; посты каналов остаются публичными в текущей модели каналов. Android-клиент поддерживает просмотр и сохранение изображений, видео и аудио в личных чатах, а также выбор нескольких файлов с последовательной отправкой отдельными сообщениями. ZIP и документы можно сохранить через системный диалог Android. Выбор нескольких файлов пока не формирует единый сгруппированный медиаальбом; анимированные изображения и встроенная запись голосовых сообщений ещё не реализованы.

Файлы сохраняются в `waysgram_media` рядом с SQLite-файлом. В Docker Compose обе папки находятся в постоянном томе `/data`. Резервные копии должны включать и SQLite, и каталог медиа.

### Внутренний BotFather

- `GET /api/bots` — список собственных ботов.
- `POST /api/bots` — создать бота; JSON: `name`, `username` (оканчивается на `_bot`), необязательные `about` и `description`. Токен возвращается только при создании.
- `GET /api/bots/by-username/{username}` — получить публичную карточку бота.
- `GET /api/bots/{id}`, `PATCH /api/bots/{id}`, `DELETE /api/bots/{id}` — управление собственным ботом.
- `POST /api/bots/{id}/token/reset` — перевыпустить токен; старый токен отзывается.
- `GET /api/bots/{id}/commands` и `PUT /api/bots/{id}/commands` — настройка списка команд.
- `POST /api/bots/{id}/messages` и `GET /api/bots/{id}/messages` — чат пользователя с внутренним ботом.
  История с `after_id` поддерживает `wait_seconds=20` для ожидания ответов без частых пустых запросов.
- `GET /api/bot-api/getUpdates?offset=...` — получить входящие сообщения по токену бота.
- `POST /api/bot-api/sendMessage` — отправить ответ пользователю по токену бота.

Каждый пользователь может иметь до 20 активных ботов. Токены хранятся в базе только в виде SHA-256 хеша. Это внутренняя система WaysGram: созданные здесь боты не становятся ботами Telegram и не получают доступ к Telegram Bot API.

### Каталог подарков Telegram из MTProto

- `GET /api/telegram/gifts` — полный каталог `payments.getStarGifts`, если настроен MTProto; в противном случае — резервный список Bot API.
- `GET /api/telegram/gifts/{gift_id}/sticker` — получить файл стикера через авторизованный серверный proxy.
- `POST /internal/v1/telegram/gifts/sync` — принудительно обновить снимок каталога; требуется `X-Internal-Token`.

**Основной источник — MTProto `payments.getStarGifts`.** AuthBot авторизует именно бота, используя `BOT_TOKEN` вместе с `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`. Официальная схема Telegram разрешает этот метод как ботам, так и пользовательским аккаунтам. Личные аккаунты и коды входа пользователей WaysGram не используются. API hash хранится только в переменных окружения. Сессионный файл бота сохраняется в `data/`, исключён из Git и получает права доступа владельца процесса.

При успешной загрузке сохраняются поля полного MTProto `StarGift`: идентификатор, документ стикера, стоимость в Telegram Stars, ограниченность, распроданность, premium-требование, лимит на пользователя, остатки, resale-поля, upgrade-цена, даты, фон и признак `auction`. Список обновляется автоматически при запросе, если последняя синхронизация старше 60 секунд. Файлы стикеров скачиваются AuthBot через MTProto и отдаются клиенту через Bearer-защищённый proxy; MTProto document и bot token на Android не передаются.

**Резервный режим:** если `TELEGRAM_API_ID` или `TELEGRAM_API_HASH` не заданы или MTProto временно недоступен, сервис загружает Bot API `getAvailableGifts`. Это только подарки, доступные для отправки AuthBot, а не полный каталог.

В поле `currency` у исходного каталога указывается `telegram_stars`. Это метаданные Telegram и они не означают, что WaysGram списывает Telegram Stars. В WaysGram-магазине используются отдельные значения `price_stars`, `supply` и `sold`, которые задаёт администратор.

Каталог Telegram хранится отдельно от внутреннего `gift_catalog`. Покупка через `POST /api/telegram/gifts/{gift_id}/purchase` — это внутренняя операция WaysGram: она списывает внутренние WaysGram Stars, уменьшает остаток магазина и записывает в инвентарь Telegram Gift ID исходного подарка. Она не отправляет подарок в Telegram, не передаёт Telegram collectible и не выполняет on-chain NFT-транзакцию. Повтор с тем же `Idempotency-Key` не списывает баланс повторно.

Управление ценой и остатком Telegram-подарков доступно только в админ-панели AuthBot. Для этого используется действие «Добавить по Telegram Gift ID»; REST-маршрута изменения цены или остатка для Android-приложения нет.

### Баланс и подарки

- `GET /api/me/wallet`, `GET /api/me/wallet/transactions` — балансы и история операций.
- `GET /api/gifts` — каталог доступных подарков.
- `GET /api/me/gifts`, `GET /api/me/gifts/transactions` — инвентарь и история передач.
- `POST /api/gifts/{id}/purchase` — покупка за Gram. Для защиты от повторного списания поддерживается заголовок `Idempotency-Key` длиной 16–128 символов.
- `POST /api/gifts/transfer` — передача принадлежащего пользователю подарка по серийному номеру и Telegram ID или username получателя. Поддерживает `Idempotency-Key`.

Покупка атомарно уменьшает баланс и остаток каталога, создаёт экземпляр с уникальным серийным номером `WG-...` и записывает операцию. Повтор того же запроса с тем же ключом идемпотентности возвращает прежний результат. Stars и Gram — внутренние единицы учёта; внешняя оплата и вывод средств этим API не реализованы.

### Системные аукционы

- `GET /api/auctions` — список активных и завершённых аукционов; при запросе выполняется завершение аукционов, срок которых истёк.
- `POST /api/auctions/{id}/bid` — ставка в JSON `{"amount":100}`; сумма указывается во внутренних Stars.

В аукцион выставляет подарок администратор через `/admin` → «Аукционы подарков». При создании один экземпляр резервируется из остатка каталога. Новая ставка должна быть не меньше стартовой и строго выше текущей. Сумма лидирующей ставки временно удерживается из баланса; при перебивании предыдущая ставка возвращается прежнему лидеру. После окончания аукциона победитель получает зарезервированный подарок. Если ставок нет, экземпляр возвращается в остаток. Отмена администратором возвращает лидирующую ставку и экземпляр подарка в каталог.

### Внутренние маршруты AuthBot

Маршруты ниже предназначены для доверенных внутренних интеграций и требуют заголовок `X-Internal-Token`:

- `POST /internal/v1/number/resolve` — проверить назначение виртуального номера.
- `POST /internal/v1/auth-code/request` — создать и доставить одноразовый код через Telegram-бота.
- `POST /internal/v1/auth-code/verify` — проверить и погасить код.
- `POST /internal/v1/telegram/gifts/sync` — обновить MTProto-каталог; при отключённом MTProto используется резервный Bot API.

`GET /health` — проверка работоспособности. Клиентские маршруты `/api/...` используют пользовательские Bearer-сессии, а не внутренний секрет.

## Админ-панель

Админ-панель доступна только внутри Telegram: аккаунт с ID `8888957702` отправляет боту команду `/admin`. Web-панели и Android-админки нет.

В панели доступны:

- **Статистика:** пользователи, блокировки, номера, активные коды, каналы, группы, внутренние боты, аукционы, личные сообщения, каталог и инвентари подарков, суммарные Stars и Gram.
- **Аккаунты:** поиск по Telegram ID, виртуальному номеру, username и отображаемому имени; карточка, блокировка и разблокировка.
- **Баланс:** начисление Stars и Gram с записью в журнал операций.
- **Подарки:** полный список каталога с постраничной навигацией, редактирование цены и остатка, скрытие, выдача и передача.
- **Аукционы:** создание и отмена системных аукционов; при отмене возвращаются удержанная ставка и зарезервированный экземпляр подарка.
- **Группы:** просмотр и удаление групп.
- **Внутренние боты:** просмотр и включение/отключение пользовательских ботов.
- **Каналы:** просмотр каналов, владельцев и числа публикаций; удаление канала.
- **Журнал:** операции с балансами, подарками, группами, ботами и административные действия.

Все административные действия ограничены `ADMIN_ID`. Блокировка аккаунта проверяется при авторизации, разрешении номера и операциях приложения.

## Текущие ограничения

Серверный API предоставляет авторизацию, профили, личные сообщения, текстовые каналы, группы, внутренний BotFather, балансы, подарки, системные аукционы, загрузку изображений, документов, ZIP, аудио и видео. Полноценные групповые медиаальбомы, анимированные вложения и звонки пока не реализованы. Для пользовательских ботов доступны команды, входящие обновления и отправка текстовых ответов; среда исполнения произвольного кода пользователя не размещается на сервере. Каталог подарков по-прежнему требует отдельной загрузки исходных карточек (ID, название, изображения, цена, лимит и признак поддержки аукциона); эти данные не создаются из общих Lottie-анимаций автоматически.


## Две базы данных

Данные разделены на два файла SQLite, которые лежат в одной постоянной папке (`/data`):

| Файл | Что хранит |
| --- | --- |
| `waysgram_authbot.sqlite3` (`DATABASE_PATH`) | аккаунты, виртуальные номера, коды входа, OTP, сессии API, журнал входов, журнал админа |
| `waysgram_authbot_messenger.sqlite3` (`MESSENGER_DATABASE_PATH`) | личные сообщения, группы, каналы, боты, подарки и аукционы, баланс грамм и звёзд (журнал операций), индекс медиа, каталог подарков Telegram |

Как это работает: ко всем соединениям с основной базой второй файл подключается как схема `messenger`. SQLite находит таблицы без указания схемы, поэтому запросы и связи с `accounts` работают как раньше. Код разделения находится в `db_split.py`.

**Обновление с одним файлом.** При первом запуске новой версии таблицы мессенджера автоматически переносятся во второй файл. Перед этим рядом с основной базой сохраняется копия `waysgram_authbot.sqlite3.pre-split.bak`. Перенос проверяется по числу строк, и исходная таблица удаляется только после успешной проверки. Повторный запуск безопасен.

Резервные копии должны включать оба файла и каталог `waysgram_media`. Оба файла должны лежать на постоянном диске.
